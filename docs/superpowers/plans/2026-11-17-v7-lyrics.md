# v7 Local Lyrics Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Turn lyrics back on with local `.lrc` files only: import a file from Now Playing, cache the parsed text per track, show timed lines, and never call the network.

**Architecture:** The parser (`src/lib/lrc.ts`), loader (`src/library/lyrics.ts`), hook (`src/library/useLyrics.ts`) and timed panel (`src/components/LyricsPanel.tsx`) already exist behind `LYRICS_ENABLED = false`. v7 flips the flag, adds an import action that reads a picked `.lrc` with the SDK 58 `File` API, stores its text in `lyrics_cache`, and reloads the hook for the same track. LRCLIB stays off; `allowNetwork` is forced false so the existing cache path serves imported text.

**Tech Stack:** Expo SDK 58, React Native 0.88, TypeScript, `expo-file-system` (`File.pickFileAsync`, `File.text`), `expo-sqlite` cache, existing `LyricsPanel`.

**Spec:** `docs/spec.md` §v7 “Lyrics, local first” and `docs/research/v7-lrclib-exploration.md`.

## Global Constraints

- Local only. No LRCLIB request, no Settings toggle, no new dependency.
- Local `.lrc` always wins over any cached value.
- Store text as-is; never rewrite the audio file or create a sidecar next to scanned media.
- Android is the target. Web keeps the panel but hides the import action (the web DB is `null`).
- Every task ends with `npm test && npx tsc --noEmit && npx expo lint && npx expo export --platform web`.
- One conventional commit per task. No push.

## Review Focus

- Picking a `.lrc` with a non-`.lrc` name must be rejected with a readable message, not parsed as lyrics.
- An empty or metadata-only `.lrc` must not replace an existing cached lyric with an empty one.
- Importing for the same track must refresh the panel without leaving and reopening Now Playing.
- A track with no lyrics must keep the panel open and offer the import action instead of auto-closing.
- A missing or unreadable file must leave the current state intact and show a note.

- [ ] **Step 3: Implement `importLyricsText` and `pickLyricsFile`**

In `importLyricsText`:
- Trim the input. Empty → throw `new Error('That file has no lyrics.')`.
- `const parsed = parseLrc(rawText)`.
- `kind = parsed.lines.length > 0 ? 'synced' : 'plain'`; `lineCount = parsed.lines.length`.

- Return `{ text: await picked.result.text(), name: picked.result.name }`.

Import `File` from `expo-file-system` and keep the module loadable under `node --test` by importing `putCachedLyrics` normally (it already degrades when the DB is `null`).

- [ ] **Step 3: Wire the import**

Add:

```ts
const [importingLyrics, setImportingLyrics] = useState(false);

async function importLyrics() {
  if (!track || Platform.OS === 'web') return;
  setImportingLyrics(true);
  setLyricsNote(null);
  try {
    const picked = await pickLyricsFile();
    if (!picked) return;
    const result = await importLyricsText(track.id, picked.text);
    lyrics.reload();
    setLyricsNote(
      result.kind === 'synced'
        ? `Added ${result.lineCount} timed lines.`
        : 'Added untimed lyrics.',
    );
  } catch (error) {
    setLyricsNote(error instanceof Error ? error.message : 'Could not read that file.');
  } finally {
    setImportingLyrics(false);
  }
}
```

Pass `onImport={Platform.OS === 'web' ? undefined : importLyrics}` and `importing={importingLyrics}` to `LyricsPanel`.
