# v7 Artwork Implementation Plan

> **For agentic workers:** REQUIRED SUB-SKILL: Use superpowers:subagent-driven-development (recommended) or superpowers:executing-plans to implement this plan task-by-task. Steps use checkbox (`- [ ]`) syntax for tracking.

**Goal:** Make the real cover drive the Now Playing backdrop, and let a chosen track or playlist image be cropped square before it is saved.

**Architecture:** Ambient color comes from a tiny local Expo module (`modules/ambient-palette`) that runs AndroidX Palette on the cover bitmap; a JS wrapper caches hex colors in AsyncStorage keyed by artwork URI and falls back to `coverColors(track.artworkHue)` on web or failure. Cropping is a new full-screen Reanimated gesture surface; `expo-image-manipulator` (SDK 58 contextual API) writes the cropped file, and the existing track/playlist persistence paths copy it into the app artwork folders. Crop geometry is a pure module with unit tests.

**Tech Stack:** Expo SDK 58, React Native 0.88, `expo-image-manipulator` ~58.0.16, `react-native-gesture-handler`, `react-native-reanimated`, AndroidX Palette in a local Expo module, `expo-sqlite` untouched.

**Spec:** `docs/spec.md` §v7 “Ambient color from the art” and “Square art cropper”.

**Prerequisite:** the UX and library-polish plan may land first; it does not touch these files except `PlaylistEditSheet` and `EditTrackScreen`. If it has landed, rebase those two files before Task 4.

## Global Constraints

- Android first. Web must still export and run with the generated hue fallback.
- No new third-party runtime dependency beyond `expo-image-manipulator` and the local module.
- Audio files are never touched. Cropped output is a new file in the app artwork folder.
- Artwork replacement must keep the old file cleanup rule of its surface: playlist commit deletes stale `<playlistId>.*`; track art may leave old files for now.
- Every task ends with `npm test && npx tsc --noEmit && npx expo lint && npx expo export --platform web`.
- One conventional commit per task. No push.

## Review Focus

- A cover with no dominant swatch (flat white, fully transparent) must fall back to the generated hue.
- A non-square cover must crop to the visible square, not stretch or letterbox.
- Pinching below 1x or panning past the edge must clamp, never expose a blank edge.
- Rotating or re-picking the device theme must not change a cached color for the same URI.
- Replacing a cover must produce a new URI, so the old cached color is not reused.

- [ ] **Step 3: Implement the Kotlin function**

Replace the generated module body with a single async function. Exact module name: `AmbientPalette`.

```kotlin
package expo.modules.ambientpalette

import android.graphics.BitmapFactory
import android.net.Uri
import androidx.palette.graphics.Palette
import expo.modules.kotlin.modules.Module
import expo.modules.kotlin.modules.ModuleDefinition

class AmbientPaletteModule : Module() {
  override fun definition() = ModuleDefinition {
    Name("AmbientPalette")

    AsyncFunction("dominantColor") { uri: String ->
      val context = appContext.reactContext ?: return@AsyncFunction null
      val bitmap = runCatching {
        context.contentResolver.openInputStream(Uri.parse(uri))?.use {
          BitmapFactory.decodeStream(it)
        }
      }.getOrNull() ?: return@AsyncFunction null

      val palette = Palette.from(bitmap).generate()
      val swatch = palette.dominantSwatch
        ?: palette.vibrantSwatch
        ?: palette.mutedSwatch
        ?: return@AsyncFunction null
      String.format("#%06X", 0xFFFFFF and swatch.rgb)
    }
  }
}
```

Keep it Android-only; delete generated iOS platform wiring from `expo-module.config.json` so web and iOS do not try to load it.

### Task 3: Crop geometry

**Files:**
- Create: `src/lib/crop.ts`
- Test: `tests/crop.test.ts`

**Interfaces:**
- Produces:
  - `export type CropTransform = { scale: number; translateX: number; translateY: number }`
  - `export type CropRect = { originX: number; originY: number; width: number; height: number }`
  - `export function clampTransform(input: { imageWidth: number; imageHeight: number; viewport: number; transform: CropTransform }): CropTransform`
  - `export function computeCropRect(input: { imageWidth: number; imageHeight: number; viewport: number; transform: CropTransform }): CropRect`

- [ ] **Step 1: Write the failing tests**

`tests/crop.test.ts` cases:
- A 1000x1000 image with `scale: 1`, no translation, viewport 300 → `{ originX: 0, originY: 0, width: 1000, height: 1000 }`.
- A 2000x1000 image with `scale: 1`, no translation, viewport 300 → crop width and height 1000, `originX` 500, `originY` 0.
- The same image with `scale: 2` → crop size 500, centered.
- A pan of `translateX: 2000` clamps so `originX` is 0 (left edge), and the opposite pan puts the crop at the right edge.
- `scale` below 1 clamps to 1.

Assert with `assert.deepEqual` on the rect and transform.

- [ ] **Step 2: Run the test to verify it fails**

Run: `node --test tests/crop.test.ts`
Expected: FAIL — module not found.

- [ ] **Step 3: Implement the geometry**

`baseScale = Math.max(viewport / imageWidth, viewport / imageHeight)`.
`displayScale = baseScale * Math.max(1, transform.scale)`.
`scaledW = imageWidth * displayScale`, `maxTx = Math.max(0, (scaledW - viewport) / 2)`; clamp `translateX` to `[-maxTx, maxTx]`; same for Y.
`cropSize = Math.min(imageWidth, imageHeight, viewport / displayScale)`.
`originX = (imageWidth - cropSize) / 2 - clampedTx / displayScale`, clamped to `[0, imageWidth - cropSize]`; same for Y. Round all four values.

- [ ] **Step 4: Run the test to verify it passes**

Run: `node --test tests/crop.test.ts`
Expected: PASS.
